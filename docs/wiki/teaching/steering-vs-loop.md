# 駕馭工程 vs 迴圈工程

## 兩種思維模式

| 面向 | 駕馭工程 (Steering) | 迴圈工程 (Loop) |
|------|---------------------|-----------------|
| 核心動作 | 人下指令、AI 執行 | 人設規則、AI 自己跑 |
| 品質來源 | Prompt 寫得好不好 | 迴圈跑幾輪、收斂條件設得好不好 |
| 適合場景 | 一次性任務、探索階段 | 重複性高、可量化品質的任務 |
| 人力成本 | 每次都要介入 | 前期設計高、後期接近零 |

## 從手動到自動的漸進路徑

1. **純手動** — 每次手寫 Prompt，人工檢查結果
2. **半自動** — Prompt 模板化，人工決定是否重跑
3. **全自動迴圈** — 設定收斂條件，讓 Agent 自己判斷「夠好了沒」

關鍵轉折點：當你發現自己在做「看結果→微調 Prompt→重跑」這個動作超過三次，就該把它變成迴圈。

## 教學設計：讓學員體驗「迴圈讓品質收斂」

### Workshop 02 的體驗流程

1. **先手動駕馭** — 學員用 Spec-Driven 寫一個 Skill，手動跑 `ark-grill-me` 檢查品質
2. **發現痛點** — 每次改完要重跑、要自己判斷哪裡沒過
3. **引入迴圈** — 把 grill → fix → grill 包成自動迴圈
4. **觀察收斂** — 看品質分數從 60 → 75 → 88 → 92 自動爬升

### 教學金句

> 駕馭工程是「你開車」，迴圈工程是「你設定導航、車自己開」。
> 兩者不衝突 — 你先學會開車，才知道怎麼設定好的導航路線。

## 實務建議

- 初學者先學 Steering，建立對 AI 能力邊界的直覺
- 有直覺後再學 Loop，把重複勞動交給機器
- Loop 的收斂條件就是你的品質標準 — 寫不出標準就回去 Steering
- 不是所有任務都適合 Loop，創意探索用 Steering 更好
