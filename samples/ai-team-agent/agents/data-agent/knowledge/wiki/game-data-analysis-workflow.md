# 遊戲數據分析工作流

## 標準分析流程

```
需求確認 → 資料取得 → 清洗整理 → 分析計算 → 可視化 → 結論產出
```

## 1. 需求確認

- 確認分析目標：「為什麼要分析？」
- 確認時間範圍：D1/D7/D30、週報、月報
- 確認維度：全體用戶 / 特定渠道 / 特定版本

## 2. 資料來源優先順序

1. 後台 BI 系統（即時）
2. 埋點原始資料（精確）
3. 渠道報告（每日同步）
4. 人工整理的 CSV（補充）

## 3. 分析方法

### Cohort 分析（留存）

```python
# 按首次登入日分組，追蹤後續留存
cohort = df.groupby(['first_login_date', 'day_offset']).user_count
retention_matrix = cohort.unstack() / cohort.unstack()[0]
```

### 漏斗分析（轉換）

```
新裝置安裝 → 完成新手引導 → 首次付費 → 第 7 天仍在玩
```

### 趨勢分析

- 7 天移動平均（平滑日波動）
- 同比/環比（與上週/上月比較）
- 異常值偵測（超過 2σ 標記）

## 4. 產出格式

| 產出物 | 格式 | 頻率 |
|--------|------|------|
| 每日日報 | Markdown + 圖表 | 每日 08:00 |
| 週報 | HTML 報告 | 每週一 |
| 專項分析 | Markdown + 數據表 | 按需 |

## 5. 與其他 Agent 協作

- **market-agent** → 提供競品數據（外部）
- **report-agent** → 接收分析結果，產出最終報告
- **pm-agent** → 確認分析需求、驗收報告

## 常見陷阱

- 避免混淆「活躍用戶」和「新用戶」
- 留存率分母要統一（使用安裝日或首登日）
- 付費數據有 T+1 延遲，注意時效
