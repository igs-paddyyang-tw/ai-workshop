🎓 課程 A：AI Agent 開發入門

🎯 體驗目的

用 Kiro IDE vibe coding（自然語言指示 AI 修改程式碼）+ Telegram 即時驗證，
在 3 堂課內讓你從零建立一個有人格、有能力、有記憶的 AI Agent。

你不需要寫程式。你只需要打字告訴 AI 你要什麼，然後去 Telegram 看結果。

🏗️ 駕馭工程（Steering Engineering）

傳統開發：你寫每一行程式碼。
駕馭工程：你設計方向，AI 執行細節。

你做的事AI 做的事
設計 SOUL（人格方向）產出符合人格的回應
拷問需求、確認 Spec依 Spec 產出程式碼
丟入知識素材建立 RAG 索引、產出有依據的回答

核心心法：你是方向盤，AI 是引擎。駕馭 ≠ 放手，駕馭 = 你決定去哪。

🚀 第一堂：Agent 初始 — 它能「說話」

🎯 課堂目標

  1. 理解 SOUL.md 如何控制 Agent 人格與回應風格
  2. 用 Inline Button 切換不同 Agent，體驗多人格系統
  3. 用 Kiro IDE 設計多種 SOUL，即時看到效果
  4. 能為真實業務場景設計合適的 SOUL

Step 1：啟動 Bot（0-5 min）

💻 終端

cd samples/ai-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python start.py

✅ 預期：「📦 Skills: 5 個」+「🤖 Bot: polling 啟動」

Step 2：切換 Agent 體驗（5-15 min）

📱 Telegram

  1. /agents → 出現 8 個按鈕
  2. 點「👑 Admin」→ 問「用一句話介紹你自己」
  3. 點「💻 Coder」→ 問同一個問題
  4. 點「🗺️ Market」→ 問同一個問題

✅ 觀察：同一個問題，4 種完全不同的回答 — 這就是 SOUL 的力量

Step 3：修改 SOUL 體驗變化（15-30 min）⭐

📝 Kiro 改成幽默風格：

打開 agents/admin-agent/.kiro/steering/SOUL.md，
把人格特質改成「幽默搞笑，每句話都帶一個冷笑話」

📱 驗證 → 問「什麼是 Python？」→ 回答帶幽默語氣

📝 Kiro 再改成專業顧問：

設計成「資深技術顧問」：嚴謹、有條理、先結論再解釋

📱 驗證 → 同一問題 → 回答變嚴謹有結構

💡 改幾行字 → Bot 完全變一個人。

Step 4：為多 Agent 設計獨特 SOUL（30-40 min）

📝 Kiro

重新設計 market-agent 的 SOUL，讓他像「新聞主播」一樣報新聞
重新設計 qa-agent 的 SOUL，讓他像「嚴格審查員」用 ❌/⚠️/✅ 標記

📱 驗證 切換 Agent 觀察風格差異

Step 5：設計真實場景（40-50 min）

📝 Kiro 選一個場景：

幫我設計一個公司客服的 SOUL.md：
- 語氣親切有禮但專業
- 邊界：不承諾退款、不給競品比較
- 格式：先問好 → 理解問題 → 回答 → 詢問還需要幫助嗎

✅ 帶走的能力：你現在能為任何業務場景設計 AI 人格。

🚀 第二堂：Skills 開發 — 它能「做事」

🎯 課堂目標

  1. 體驗「被拷問」如何讓設計決策更清晰
  2. 產出一份可驗證的 Spec（有目標、有驗收條件）
  3. 用自然語言觸發 Skill 產出完整功能
  4. 理解「先 Spec → 再 Code → 再驗證」的開發方法

🔧 Spec-Driven 完整迴圈

ark-grill-me → ark-superpowers → ark-skill-creator → ark-code-spec-validator
 （想清楚）       （寫規格）         （依規格做）          （驗證一致）

Step 1：為什麼需要 Skill（0-5 min）

📱 Telegram 問 Admin「幫我分析這段程式碼的效能問題」

觀察：Agent 只能通用回答，沒有專門能力 → 需要 Skill 擴充

Step 2：拷問設計（5-20 min）⭐

📝 Kiro

拷問我的設計：我想為 market-agent 開發一個新的新聞爬蟲 Skill，
支援多來源併發抓取 + 失敗自動重試 + 結構化 JSON 輸出

→ AI 一次問一個問題（8-15 題）

⚠️ 你的角色：不要全部回「好」「OK」。質疑、補充、控制範疇。

✅ 產出：決策摘要表格（6-10 個已確認的設計決策）

Step 3：產出 Spec（20-35 min）

📝 Kiro

根據以上決策摘要，幫我寫 spec

✅ 產出：docs/specs/news-scraper-spec.md（含可量化驗收條件）

Step 4：依 Spec 產出 Skill（35-45 min）

📝 Kiro

建立新 Skill：科技新聞爬蟲，根據 docs/specs/news-scraper-spec.md 實作

✅ 產出：agents/market-agent/skills/ark-news-scraper/SKILL.md

Step 5：驗證一致性（45-50 min）

📝 Kiro

驗證 code 跟 spec 一致嗎

✅ 產出 Drift Report → Score ≥ 90 可上線

🚀 第三堂：LLM Wiki — 它能「記住」

🎯 課堂目標

  1. 在 Kiro IDE 內完成知識庫建構 + 驗證 RAG 有效
  2. 讓 Agent 學會「你教它的東西」
  3. 部署到 Telegram 確認使用者也能拿到正確答案
  4. 理解自演化：每次對話都在讓 Agent 變聰明

📂 知識庫案例：遊戲競品分析

檔案內容
ocean-king-analysis.mdOcean King 2/3/4 捕魚機系列比較
super-ace-analysis.mdSuper Ace 老虎機 Golden Card 機制
fishing-vs-slot-comparison.md捕魚機 vs 老虎機產品定位

Step 1：建立基準 — 還沒 ingest（0-5 min）

📝 Kiro

查詢 Wiki「Ocean King 系列捕魚機跟競品的差異」

✅ 預期：查不到（raw/ 有素材但 wiki/ 是空的 → 還沒 ingest）

💡 素材存在 ≠ 知識可用。

Step 2：匯入知識 + Kiro 內驗證（5-20 min）⭐

📝 Kiro

匯入 knowledge/raw/ 的所有文件到 Wiki
再查一次「Ocean King 系列跟競品的差異」

✅ 預期：找到 Ocean King 2/3/4 具體差異 — RAG 生效！

Step 3：建自己的知識（20-35 min）

📝 Kiro

在 knowledge/raw/ 建立 slot-market-trends.md：
2024-2025 老虎機市場趨勢，包含東南亞市場、玩法趨勢、競爭格局
匯入到 Wiki
查詢「東南亞老虎機市場誰是主要玩家」

✅ 預期：回傳 JILI、PG Soft、Pragmatic Play

Step 4：Telegram 上線驗證（35-45 min）

📱 Telegram

  1. 問「Ocean King 3 跟 Ocean King 2 有什麼差別？」→ 有「📚 參考」引用
  2. 問「Super Ace 的 Golden Card 怎麼觸發？」→ 有引用
  3. 問「PG Soft 的 Mahjong Ways 怎麼玩？」→ 沒資料 → 坦白說

💡 能回答有引用，不能的坦白說 = 可信任的 AI

Step 5：自演化觀察（45-50 min）

📝 Kiro

列出 agents/admin-agent/knowledge/raw/ 的檔案

✅ 看到 memory 自動記錄 → 定期 ingest → Agent 越用越聰明
