你只需要描述目標，pm-agent（leader）自動拆解任務、選人、排序、執行。

🔄 迴圈工程（Loop Engineering）

課程 A 教的是「線性流程」：輸入 → 處理 → 輸出。
課程 B 教的是「迴圈系統」：輸出會回饋成下次的輸入，系統自動進化。

        ┌─────────────────────────────────────┐
        │                                     ▼
  派工 → 執行 → 產出 → 記憶 → 知識成長 → 下次更準
        ▲                                     │
        └─────────────────────────────────────┘

  排程觸發 → 自動派工 → 自動執行 → 自動累積 = 無人值守的成長迴圈
線性（課程 A）迴圈（課程 B）
你 /assign → Agent 做一次排程自動觸發 → Agent 每天做
你加知識 → Agent 能回答Agent 自己累積記憶 → 越來越準
一個 Agent 做一件事一群 Agent 分工 → 結果互相依賴
Demo 等級生產等級

核心心法：設計迴圈，不是設計步驟。讓系統自己跑、自己學、自己成長。

🚀 第四堂：Agent Team — 它們能「合作」

🎯 課堂目標

  1. 用 Kiro 自然語言建立 + 修改團隊配置
  2. 理解 team.yaml 如何控制「誰做什麼」
  3. 在 Telegram 驗證團隊派工 + 分工 = 可上線
  4. 動手擴展團隊（加新 Agent）

前半段：Kiro IDE 開發

Step 1：啟動團隊平台（0-5 min）

💻 終端

cd samples/ai-team-agent
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python start.py

✅ 預期：「5 Agents ready」+「Telegram Bot 已啟動」

Step 2：理解團隊配置（5-15 min）

📝 Kiro

打開 team.yaml，用表格列出每個 Agent 的 role、description
比較 team-ops.yaml 和 team-dev.yaml 的差異

✅ 理解：team.yaml = 組織圖。改這個就改了分工。

Step 3：加新 Agent（15-25 min）⭐

📝 Kiro

在 team.yaml 加入新 Agent：
- id: designer-agent
- description: "🎮 遊戲設計師 — 遊戲 UI、視覺風格、玩法體驗分析"
- role: worker
- working_directory: agents/designer-agent
用 ark-kiro-init 幫 designer-agent 初始化完整 .kiro/ 配置：
- SOUL：遊戲設計師，熟悉手遊 UI 設計、玩法機制
- knowledge/raw/ 放一份「手遊設計原則」作為種子知識

✅ 預期產出完整結構：.kiro/steering/SOUL.md + MEMORY.md + USER.md + knowledge/raw/

後半段：Telegram 上線驗證

Step 4：派工驗證（25-40 min）

💻 重啟 → 📱 Telegram

4.1 指令式派工

/agents → 看到 6 個 Agent
/assign 規劃科技日報：market 抓新聞、data 做分析、report 產出 HTML 日報
/board → 看任務狀態

4.2 自然語言派工（同一任務）

@pm 規劃科技日報：market 抓新聞、data 做分析、report 產出 HTML 日報
/assign@pm
方式指令式自然對話
結果相同相同
適合明確派工像跟人說話

Step 5：驗證新 Agent — 捕魚機競品分析（40-50 min）

📱 Telegram

/assign 捕魚機遊戲競品分析與設計報告：market 蒐集市面捕魚機遊戲資料、designer 分析遊戲 UI 風格和玩法設計、report 產出競品分析報告

✅ 預期：designer-agent 接到任務 → 3 Agent 協作 → 產出報告

📱 加碼

@pm 根據剛才的競品分析報告，產出一份新捕魚機遊戲的專案提案書

💡 你加的 Agent 馬上能跟團隊合作。加人 = 改 yaml + 初始化 .kiro/

🚀 第五堂：營運落地 — 它能「自己跑」

🎯 課堂目標

  1. 設定排程讓科技日報每天自動產出（不用手動 /assign）
  2. 設定費用上限避免 AI 燒錢（cost_guard）
  3. 用後台 API 看任務執行狀況
  4. 理解「Demo → 正式上線」需要什麼

前半段：Kiro IDE 設定

Step 1：設定排程（0-10 min）⭐

📝 Kiro

打開 scheduler.yaml，加入排程：
- id: daily-tech-news
- 時間: 每天早上 09:00（Asia/Taipei）
- 任務: market 蒐集新聞、report 產出日報
- 指派: pm-agent
加入第二個排程：
- id: weekly-competitor-report
- 時間: 每週一 10:00
- 任務: market + designer + report 產出捕魚機競品週報

✅ 預期：scheduler.yaml 有 2 個排程

Step 2：設定費用控管（10-20 min）

📝 Kiro

打開 team.yaml 的 cost_guard，把 daily_limit_usd 改成 5.0，
解釋超過上限會發生什麼

✅ 理解：超過 → 新任務被拒 + 通知 admin

Step 3：重啟確認（20-25 min）

💻 終端

python start.py

🌐 curl

curl http://localhost:33333/api/admin/schedules

✅ 列出 2 個排程 + 下次觸發時間

後半段：驗證自動運作

Step 4：手動觸發 + 看結果（25-40 min）

🌐 curl 手動觸發排程：

curl -X POST http://localhost:33333/api/admin/schedules/daily-tech-news/trigger

📱 Telegram

  • 觀察 pm-agent 自動拆解 → market 抓新聞 → report 產日報
  • /board 看排程觸發的任務
  • /costs 看費用消耗

🌐 curl 後台統計：

curl http://localhost:33333/api/admin/dashboard/stats

✅ 預期：agents_online: 6, tasks_today: 3, cost_today_usd: 0.12

Step 5：上線 Checklist（40-50 min）

📝 Kiro

幫我列出這個 Agent Team 正式上線前的 Checklist：

✅ 產出清單：

類別項目狀態

費控daily_limit_usd 設定✅
監控/board + /costs 能看✅
